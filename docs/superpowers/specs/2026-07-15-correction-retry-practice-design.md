# 교정 문장 다시 말하기 연습 설계

## 목표

학습자가 방금 말한 문장의 의미를 유지한 자연스러운 교정 문장을 짧게 다시 말해보게 한다. 연습은 선택 사항이며, 성공하면 소량의 LP를 지급한다. 연습 발화는 AI 프리토킹 흐름에 영향을 주지 않아야 한다.

## 범위

이번 작업은 다음을 포함한다.

- 평가 패널의 최신 교정 카드에 `다시 말하기 +2 LP`와 `넘어가기` 동작 추가
- 기존 WebSocket과 STT를 재사용하는 세션 전용 연습 모드 추가
- 연습 발화와 일반 대화 발화의 서버 경로 분리
- 결정적 문장 유사도 판정과 세션당 1회 LP 지급
- 성공, 실패, 취소, 시간 초과, 연결 종료 상태 처리
- 관련 프론트엔드와 백엔드 테스트

이번 작업은 다음을 포함하지 않는다.

- `learnerId` 기반 영구 저장
- 발음 정확도 평가
- LLM을 이용한 의미 유사도 판정
- 기존 미션 시스템 또는 배치 평가 규칙 변경
- 프론트엔드와 백엔드 사이의 기존 이벤트 형식 변경

## 사용자 경험

의미 있는 교정 문장이 준비되면 최신 교정 카드에 다음 내용을 표시한다.

1. 제목: `다음에는 이렇게 말해보세요`
2. 교정 문장
3. 어린 학습자도 이해할 수 있는 짧은 한국어 설명
4. `다시 말하기 +2 LP` 버튼
5. `넘어가기` 버튼

연습 상태는 다음과 같다.

| 상태 | 화면 | 가능한 동작 |
| --- | --- | --- |
| 준비 | `다시 말하기 +2 LP` | 연습 시작, 넘어가기 |
| 듣는 중 | `듣고 있어요…`와 취소 버튼 | 말하기, 취소 |
| 판정 중 | `확인하고 있어요…` | 결과 대기 |
| 성공 | `잘했어요! +2 LP` | 카드 접기 |
| 실패 | 인식된 문장과 `한 번 더` | 재시도, 넘어가기 |
| 오류 | 짧은 오류 안내 | 재시도, 넘어가기 |

항상 최신 교정 한 건만 연습 대상으로 둔다. 새 교정이 도착하면 이전 연습을 취소한다. 원문과 교정문이 실질적으로 같거나 교정문이 비어 있으면 다시 말하기 버튼을 표시하지 않는다.

AI 음성이 재생 중일 때는 연습 버튼을 비활성화한다. 일반 대화를 방해하지 않도록 연습 카드의 성공 또는 실패 결과는 채팅 메시지로 추가하지 않는다.

## 데이터 흐름

### 연습 시작

프론트엔드는 다음 제어 메시지를 기존 WebSocket으로 보낸다.

```json
{
  "type": "practice_start",
  "sourceTurnId": "turn-123",
  "target": "I went to the library yesterday."
}
```

백엔드는 다음을 검증한 뒤 해당 WebSocket 세션에 연습 상태를 저장한다.

- `sourceTurnId`와 `target`이 문자열인지
- 대상 문장 길이가 1~300자인지
- 다른 연습이 진행 중이지 않은지
- 세션에서 이미 성공한 `sourceTurnId`가 아닌지

연습 상태에는 대상 턴, 대상 문장, 시작 시각만 저장한다. 20초 안에 최종 발화가 없으면 자동 취소한다.

### 음성 처리

기존 PCM 오디오와 STT 경로를 그대로 사용한다. 단, 연습 모드에서는 STT 콜백이 일반 대화 경로로 들어가기 전에 분기한다.

- 임시 인식: `partial_user_request` 대신 `practice_partial` 전송
- 최종 인식: 대화 파이프라인을 호출하지 않고 유사도 판정
- `final_user_request`, 교정 요청, 배치 평가 등록, 미션 판정, LLM 생성, TTS 생성을 수행하지 않음
- 대화 history와 프론트 `messages`에 연습 발화를 추가하지 않음

최종 결과는 다음 형식으로 전송한다.

```json
{
  "type": "practice_result",
  "sourceTurnId": "turn-123",
  "transcript": "I went to the library yesterday.",
  "score": 0.94,
  "success": true,
  "rewardLp": 2
}
```

기존 이벤트는 변경하지 않고 새 이벤트만 추가한다. 기존 프론트엔드는 새 이벤트를 모르면 무시할 수 있으므로 하위 호환성을 유지한다.

### 취소

프론트엔드는 사용자가 취소하거나 새 교정이 도착했을 때 다음 메시지를 보낸다.

```json
{
  "type": "practice_cancel",
  "sourceTurnId": "turn-123"
}
```

백엔드는 현재 연습 상태를 제거하고 일반 대화 모드로 복귀한다. WebSocket 연결 종료 시에도 연습 상태를 폐기한다.

## 성공 판정

판정은 서버에서 결정적으로 수행한다. LLM은 사용하지 않는다.

정규화 단계:

- Unicode 정규화
- 영문 소문자화
- 문장부호 제거
- 연속 공백 정리
- 일반적인 영어 축약형 정규화

점수는 문자 시퀀스 유사도와 단어 일치도를 조합한다. 성공 조건은 다음 두 조건을 모두 만족하는 것이다.

- 조합 점수 0.78 이상
- 대상 문장의 핵심 단어 포함률 0.75 이상

관사와 일부 짧은 기능어 누락은 허용하되, 동사·명사·형용사 등 핵심 단어가 크게 빠진 문장은 실패한다. 문장이 3단어 이하인 경우에는 과도한 오판을 막기 위해 조합 점수 0.9 이상을 요구한다.

발음 평가는 제공하지 않는다. STT 결과와 대상 문장의 문장 재현만 판정한다는 점을 화면 문구에서 과장하지 않는다.

## LP와 상태

성공한 연습은 프론트 상태의 해당 사용자 메시지에 다음 형태로 기록한다.

```ts
type CorrectionPracticeCompletion = {
  sourceTurnId: string;
  transcript: string;
  score: number;
  rewardLp: 2;
  completedAt: string;
};
```

LP 합산 함수는 완료 기록의 `rewardLp`를 기존 발화 LP와 미션 LP에 더한다. 같은 `sourceTurnId`의 완료 기록은 한 번만 허용한다. 서버도 세션 내 성공 턴 집합을 유지해 중복 성공 응답을 막는다.

현재 LP는 세션 범위다. 마이크만 껐다 켜는 경우 WebSocket과 대화 세션이 유지되므로 완료 기록도 유지한다. 명시적 대화 초기화 또는 세션 종료 시 제거한다. 추후 `learnerId`가 도입되면 동일한 완료 구조를 영구 저장 계층에 연결한다.

## 오류 처리

- 마이크 권한 거부: 프론트에서 연습을 시작하지 않고 카드에 권한 안내 표시
- WebSocket 미연결: 버튼 비활성화 및 연결 안내
- STT 오류: LP 변경 없이 오류 상태로 전환
- 20초 무발화: 백엔드가 연습 상태를 제거하고 `practice_timeout` 전송
- 새 교정 도착: 이전 연습 취소 후 최신 교정으로 카드 갱신
- AI TTS 시작: 진행 중인 연습이 없다면 버튼 비활성화. 진행 중이라면 연습을 취소해 오디오 혼입 방지
- 연결 종료: 서버와 프론트 모두 연습 상태 초기화. 기존 대화 복구 정책은 변경하지 않음
- 잘못된 제어 메시지: 서버는 세션을 종료하지 않고 `practice_error`를 반환

## 컴포넌트 경계

### 프론트엔드

- `CorrectionCoachCard`: 교정 내용과 연습 상태 표시, 시작·취소·재시도 이벤트 전달
- `useVoiceSocket`: 연습 제어 메시지 전송, 새 연습 이벤트 수신, 일반 발화 이벤트와 분리
- `useStore`: 현재 연습 상태와 턴별 완료 기록 저장, 중복 LP 방지
- LP 계산 유틸리티: 연습 보상을 기존 총 LP에 합산

`AssessmentPanel`에 WebSocket 프로토콜 로직을 직접 넣지 않는다. 카드는 상태를 표시하고 사용자 의도를 전달하는 역할만 가진다.

### 백엔드

- WebSocket 입력 처리: `practice_start`, `practice_cancel` 검증과 세션 상태 전환
- 전사 콜백: 연습 모드에서 일반 대화 파이프라인 이전에 분기
- 문장 비교 유틸리티: 정규화와 점수 계산을 순수 함수로 제공
- 세션 상태: 현재 연습과 성공한 대상 턴 집합 저장

전역 상태나 사용자 간 공유 캐시를 사용하지 않는다. 연습 상태는 해당 WebSocket 세션에만 속한다.

## 테스트

### 백엔드

- 정규화와 유사도 판정 단위 테스트
- 짧은 문장, 축약형, 문장부호, 기능어 누락, 핵심 단어 누락 경계값 테스트
- 연습 모드 최종 발화가 LLM/history/교정/평가/TTS를 호출하지 않는 테스트
- 성공 후 같은 턴 재시도 시 LP가 다시 발급되지 않는 테스트
- 취소, 시간 초과, 잘못된 입력, 연결 종료 테스트
- 일반 발화의 기존 이벤트 회귀 테스트

### 프론트엔드

- 카드의 준비·듣기·판정·성공·실패·오류 상태 테스트
- 새 교정 도착 시 이전 연습 취소 테스트
- 연습 결과가 `messages`에 추가되지 않는 테스트
- 성공 LP가 총 LP에 한 번만 포함되는 테스트
- 마이크 중지·재시작 후 완료 기록 유지 테스트
- 기존 평가 패널, 미션, 배치 상태 렌더링 회귀 테스트

### 실사용 검증

`http://localhost:3003/chat`에서 다음을 확인한다.

1. 일반 대화 한 턴 후 교정 카드 노출
2. 다시 말하기 성공 후 AI가 중복 응답하지 않음
3. 채팅 턴 수와 평가 대기 수가 증가하지 않음
4. LP가 정확히 2 증가하고 반복 시 증가하지 않음
5. 실패 후 재시도와 건너뛰기가 정상 동작
6. 마이크를 껐다 켜도 대화와 완료 상태 유지

## 배포와 롤백

백엔드를 먼저 배포한 뒤 프론트엔드를 배포한다. 새 이벤트만 추가하므로 구버전 프론트와 호환된다. 프론트만 먼저 배포된 경우 서버가 `practice_error` 또는 무응답일 수 있으므로 일정 시간 후 카드가 일반 상태로 복귀해야 한다.

문제가 발생하면 프론트의 다시 말하기 버튼을 숨겨 기능을 비활성화할 수 있다. 기존 대화, 평가, 미션 경로는 연습 분기 외에는 변경하지 않으므로 해당 분기와 이벤트 핸들러를 제거하면 원래 동작으로 복귀한다.
